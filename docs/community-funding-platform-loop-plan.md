# AuditMap Community Funding And Coverage Loop Plan

## Current-Model Reset: MVP Decision

This plan was re-evaluated from first principles on August 4, 2026. The mission and trust model remain sound, but the first release is intentionally narrower than the broader roadmap below.

The MVP is one place-level loop:

1. Show one honest, costed next milestone on a place page.
2. Let people signal what they would contribute before payments are enabled.
3. Record that demand and use it to choose the first real campaigns.
4. When payments launch, pool small contributions toward the milestone.
5. Publish status and the completed public result on the same page.

The MVP does not initially include city funds, recurring support, paid contributor task claiming, donor accounts, compute-token donation, or API billing. Those ideas remain valid follow-ons, but each adds operational promises that should be informed by real fulfillment costs.

### Launch economics

Only four work packages should appear in the first pilot:

| Work package | Pilot target | Public result |
| --- | ---: | --- |
| Photo and source pack | $25 | Useful, licensed or official images with source and attribution review. |
| Question sprint | $75 | Researched answers to the most important unresolved visitor questions. |
| Subsite mapping pass | $150 | Entrances, parking, restrooms, trailheads, and other useful internal destinations. |
| Accessibility and arrival audit | $250 | Verified arrival, parking, entrance, surface, restroom, and access details. |

The `$500` rich-media package should wait until a real 360 workflow, equipment plan, travel policy, hosting cost, privacy review, and sample deliverable exist. The `$1,250` and `$5,000` packages should wait until smaller work has been fulfilled repeatedly and actual margins are known.

### Financial promise

Backing funds a defined public work pool, not a purchase of facts and not a guaranteed personal service. Before accepting money, every live campaign must state what happens if it is overfunded, underfunded, delayed, impossible to fulfill, or canceled. Compatably, LLC must also have a written refund and reallocation policy.

## Purpose

This plan turns AuditMap's existing contribution, stewardship, moderation, and enrichment systems into a public coverage loop that can help fund ongoing rollout after North Carolina enrichment is complete.

The goal is not to put basic public facts behind a paywall. The goal is to let the public help fund faster coverage, deeper verification, richer media, and fieldwork for the places they care about.

## Operating Decision

As of August 4, 2026, AuditMap's near-term rollout should use `Compatably, LLC` as the operating vehicle.

This means the first public funding loop should be framed as:

- public support
- backing
- sponsorship
- funding coverage work

It should not be framed as tax-deductible charitable giving unless and until a separate qualifying nonprofit or fiscal sponsor is in place.

This decision is about speed and operational simplicity during rollout. It does not prevent a future nonprofit structure, fiscal sponsor relationship, or hybrid model where a nonprofit stewards the mission and Compatably operates platform services.

## Core Thesis

AuditMap should treat funding as a way to sponsor public work:

- fund this place
- fund this park
- fund this area
- fund this city
- fund this category

Public funding should unlock:

- faster research
- more complete facts
- fresher records
- richer images and media
- subsite mapping
- local field verification
- accessibility and arrival detail

Public funding should not unlock:

- exclusive facts for donors only
- private truth claims
- donor control over moderation or verification outcomes
- publication of unsupported claims

## Mission Position

AuditMap's mission in this operating phase is:

- make public-place information more accessible
- keep useful information available without a paywall
- use community participation to reduce dependence on advertising
- reduce dependence on closed, corporate information gatekeepers
- create a more public-serving alternative to search-and-review monopolies

The product should be built so that people can help fund and improve the public record without recreating the same extractive patterns used by ad-heavy platforms.

## Product Principles

1. Core verified facts stay public.
2. Money pays for coverage depth, freshness, and labor.
3. Every funded task must map to a visible public outcome.
4. Every funded task must go through the same trust and review rules as any other record change.
5. Donors can influence priority, but not truth.
6. Small donations should aggregate into meaningful milestones instead of pretending `$5` alone buys a complete work item.

## The Platform Loop

The platform loop should work like this:

1. AuditMap shows a useful but incomplete public record.
2. The page makes missing work visible.
3. Visitors fund the next layer of work for a place, area, or city.
4. Contributors, stewards, researchers, and field mappers complete that work.
5. AuditMap reviews, verifies, and publishes the result.
6. The page visibly improves and shows what the funding accomplished.
7. Better pages attract more trust, more contributors, and more funding.
8. API and partner revenue help subsidize additional public coverage.

## What Already Exists In AuditMap

The current product already has important building blocks:

- community contribution feed
- moderation and review inbox
- claim extraction and evidence model
- place stewards and steward applications
- information-needs queue
- enrichment queue and completeness work
- place pages with facts, photos, and community context

That means the shortest path is not building a funding system from scratch. The shortest path is connecting funding to the work queues and publication flow you already have.

## Recommended First Funding Model

Use a hybrid model with four revenue lanes:

1. **Public donations**
   Fund a place, city, category, or statewide workstream. In the LLC phase, describe these as support, backing, or sponsorship rather than charitable donations.
2. **Sponsored coverage**
   Institutions, conservancies, and aligned partners fund public coverage without controlling verification outcomes.
3. **Commercial API and data access**
   Free or low-cost access for public-interest use cases, paid access for commercial, bulk, or high-volume use.
4. **Grants and philanthropy**
   Support the public-interest layer, especially accessibility, undercovered areas, and civic knowledge work.

## Milestone Strategy

### Important framing

The example amounts from brainstorming are directionally useful, but some are too low to represent real standalone work. The safer product strategy is:

- allow small donations like `$5`
- pool them into milestone buckets
- publish only milestones that reflect real operating costs

So the public message becomes:

- `$5` helps fund the next photo or refresh milestone
- `$125` helps fund a field verification pool
- `$500` helps fund richer media or a more complete on-site audit

### Starting milestone menu

These are planning estimates for the current rollout, not final accounting numbers. They should be recalibrated after the first 20 to 30 funded jobs.

| Milestone | Suggested public label | Initial target | What it funds |
| --- | --- | ---: | --- |
| 1 | Photo and source pack | $25 | Research time to add 1 to 3 better source-cited images or source links for a place or subsite. |
| 2 | Freshness check | $40 | Re-check hours, closures, fees, and official visitor details against current primary sources. |
| 3 | Question sprint | $75 | Answer and document the top unresolved visitor questions for a place using official sources. |
| 4 | Subsite mapping pass | $150 | Add or improve internal destinations such as entrances, parking, restrooms, trailheads, or playgrounds. Mostly desk research with source review. |
| 5 | Local field verification stipend | $175 | Pay a trained local contributor to visit, verify, photograph, and document a defined checklist. |
| 6 | Accessibility and arrival audit | $250 | Produce a more complete visit-focused pass on parking, entrances, surfaces, restrooms, and arrival friction. |
| 7 | Rich media pack | $500 | Add a richer visual layer such as 360 capture, expanded photo set, or a more complete internal navigation pass. |
| 8 | Anchor place completion | $1,250 | Bring a high-value destination close to the full-buildout standard with facts, images, questions, and subsites. |
| 9 | City anchor bundle | $5,000 | Fund the next priority set of anchor destinations in one city or district. |

### Recommended donor-facing interpretation

- `$5` = join this place's photo and refresh fund
- `$25` = help complete the next concrete milestone
- `$125` = materially support local verification
- `$500` = sponsor a richer media or on-site audit milestone

This keeps micro-donations welcome without making false promises about unit economics.

## What Money Can Reasonably Buy

For the current rollout, money can realistically pay for six kinds of work:

1. **Desk research**
   Official source review, hours, fees, closures, contacts, and visitor details.
2. **Media sourcing**
   Better official or Commons imagery, attribution cleanup, and missing alt text.
3. **Question resolution**
   Targeted answers to specific public information gaps already tracked by AuditMap.
4. **Subsite production**
   Entrances, lots, trailheads, restrooms, playgrounds, beaches, visitor centers, and other internal destinations.
5. **Field verification**
   Structured paid or reimbursed visits by trained contributors.
6. **Platform operations**
   Moderation, QA, compute, storage, and fulfillment overhead.

Money should not be casually promised for:

- same-day custom field trips everywhere
- broad unrestricted contractor labor without a scoped checklist
- expensive custom video production on low-value pages
- donor-directed factual claims that bypass review

## Compute Funding Strategy

Do not launch with literal "donate your own tokens" mechanics.

Start with a simpler and safer model:

- sponsor refresh checks
- sponsor enrichment runs
- sponsor question-answering work
- sponsor a city's monthly research budget

Internally, each funded milestone can allocate a fixed share to platform operations:

- `60%` direct labor or fulfillment
- `20%` platform operations and compute
- `10%` QA and moderation
- `10%` reserve for payment fees, failed tasks, or follow-up work

These percentages are starter assumptions. They should be updated once real costs are measured.

## Rollout Sequence

### Phase 0: Finish North Carolina enrichment and define the funding inventory

Target window: immediately after the current NC enrichment push on August 4, 2026

Deliverables:

- freeze an initial list of fundable scopes:
  - individual place
  - parent park with subsites
  - city anchors
  - NC district
  - statewide category
- mark each scope with current completeness and next-best funded work
- create a private cost catalog for standard work items
- choose one public pilot category

Recommended pilot:

- major parks first

Why:

- milestones are intuitive
- photos and subsites matter
- field verification is valuable
- donors can understand the outcomes quickly

### Phase 1: Add funding metadata without payments

Goal: build the public and internal loop before handling money

Deliverables:

- show missing work modules on place pages
- show "fund this place" and "fund this city" calls to action
- create campaign records and milestone definitions in Supabase
- add internal admin views for campaign status
- allow manual sponsorship marking for testing
- display a public progress bar and a public completion ledger

Success criteria:

- every pilot page can show what is done, what is missing, and what the next milestone funds
- internal team can manually move a page from funded to in-progress to reviewed to published

### Phase 2: Launch donations and sponsorships

Goal: accept money for public work in a narrow, controlled pilot

Deliverables:

- checkout flow for one-time donations
- optional recurring city or category support
- donor note with scope targeting
- milestone progress bars
- public receipt language that explains the donation funds public coverage work, not guaranteed private services
- admin payout and fulfillment queue

Success criteria:

- first real funded milestones complete end-to-end
- donors can see the public result of the work
- moderation and trust standards remain unchanged

### Phase 3: Add paid fieldwork and steward escalation

Goal: convert funded tasks into reliable local completion

Deliverables:

- field verification checklist templates
- contributor and steward reputation signals
- paid task acceptance flow for trusted contributors
- upload and evidence requirements for funded field tasks
- post-task review checklist in admin

Success criteria:

- AuditMap can route a funded task to a person, review the result, and publish it safely

### Phase 4: Add API monetization

Goal: let commercial use help support the public platform

Deliverables:

- API keys
- usage metering
- tiered limits
- civic or public-interest free tier
- commercial paid tier
- bulk export or partner tier

Success criteria:

- commercial users can pay for dependable access
- public-interest users still have a viable free path
- API revenue can be tied back to public coverage expansion

## Public Messaging Strategy

Recommended language:

- `Help complete this record`
- `Fund deeper verification`
- `Sponsor fresh updates`
- `Support mapping for this city`
- `Back public information for this park`
- `Keep this information free and public`
- `Help build a public alternative to ad-driven local discovery`

Avoid:

- `unlock the truth`
- `pay to verify`
- `buy access to facts`
- `fund the answer you want`
- `tax-deductible donation` unless the legal structure changes
- `charitable contribution` unless the legal structure changes

## LLC-Phase Positioning Rules

While AuditMap operates through `Compatably, LLC`, the product should follow these rules:

1. No claim that public support is tax-deductible unless a qualifying structure is later added.
2. No suggestion that donors are purchasing favorable facts or moderation outcomes.
3. No basic public-fact paywall.
4. No ad-first product decisions that compromise the mission.
5. Commercial API access should subsidize public access rather than replace it.
6. Every funding request should explain the public work it enables.

## Suggested Public Positioning

Short internal positioning sentence:

`AuditMap is building a public-serving, crowd-supported place-information platform that keeps useful civic and visitor information accessible without relying on paywalls, ad clutter, or closed platform gatekeepers.`

Short supporter-facing positioning sentence:

`Support public place information that stays open, useful, and community-built.`

## Pilot Scope Recommendation

After NC enrichment is stable, launch the pilot in this order:

1. Raleigh flagship parks and destination pages
2. Wave 1 city anchor parks
3. Major parks in the nationwide launch list
4. City-level funding bundles

This sequence keeps the pilot legible and helps AuditMap learn on pages where visual, spatial, and fieldwork upgrades are obvious to donors.

## Commercial API Strategy

Use the public platform to generate trust, then monetize higher-intent use:

- free public browsing
- free or discounted civic, research, accessibility, and nonprofit usage
- paid commercial API access
- paid bulk export and integration tier
- paid partner tools for embeds, reporting, or stewardship workflows

Commercial API revenue should be framed as a mission subsidy:

- companies pay for dependable access
- the public gets better open coverage as a result

## Immediate Implementation Backlog

### Track A: planning and data model

1. Define the first 10 to 20 pilot funding scopes from live NC pages.
2. Write the initial milestone catalog with real internal cost assumptions.
3. Extend `supabase/schema.sql` with campaign, milestone, contribution, task, and update tables.
4. Decide the first payment path and accounting owner.

### Track B: product scaffolding

1. Add a read-only funding card to the place page.
2. Add a missing-work checklist driven by completeness gaps.
3. Add public progress bars and milestone labels.
4. Add internal admin views for activating and completing milestones.

### Track C: fulfillment

1. Write desk-research and field-verification checklists.
2. Define evidence requirements for each milestone type.
3. Define who can fulfill which task type.
4. Add public update posts tied to each funded milestone.

### Track D: monetization follow-on

1. Define free and paid API usage classes.
2. Add API keys and request metering.
3. Create public-interest exceptions and partner rules.

## Decisions To Make Before Coding

These choices affect implementation shape:

1. Whether the first live funding pilot accepts real money immediately or starts as a manual pledge system.
2. Whether field verification is volunteer-first, paid-first, or hybrid.
3. Whether place-level or city-level funding is the primary public call to action.
4. Whether API monetization starts in the same phase or after the donor loop proves itself.

## Recommendation

For the current rollout, the safest and fastest path is:

1. Finish NC enrichment.
2. Pilot funding on major parks.
3. Launch funding metadata and public progress bars before real payments.
4. Turn on real funding after the fulfillment and review loop works manually.
5. Add API monetization after the public funding loop is legible.

This preserves trust, keeps scope manageable, and turns today's enrichment and moderation systems into the nucleus of a much bigger public platform.
